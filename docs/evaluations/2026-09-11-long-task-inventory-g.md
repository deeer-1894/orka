# 长复杂任务实测 G：持续推进优化对照

本轮使用 F 的同一库存任务，仅替换测试编号和新输出目录；计算公式、调研上限、复现和验收要求不变。F 原始产物与独立基线均保留。**本轮终态为 partial，尚未完整通过。** 开始行动更快、数据及图表更正确、交付更齐全，但总耗时和用量增加，收尾仍触及预算。

## 本轮实现

- 服务层仅对已验证的 DeepSeek V4 型号发送 low 推理强度；保持首轮4096、后续8192输出上限、最多一次截断重试及每次逻辑调用180秒期限。
- 传输层保留接受的 assistant 工具调用思考内容，拒绝提前结束或损坏的响应，并保留完整解析到的报费用量。
- 每次上下文整理后重申小步推进、提前业务断言；改变的已声明小文件自动做有界结构检查。结构检查通过不代表业务正确。
- 有实际工具进度的调用触限保留 partial、原始错误、未完成项和累计预算；取消与终态持久化保持一致，断点里的零进度不从展示文本猜测覆盖。
- 聊天页按当前运行恢复，区分断点继续和重新执行；文件按确切路径和实际存在性关联，排除失败/拒绝写入及思考中的文件名。

## 独立验收

终态业务比较 **345/345通过**：raw/clean/rejected/daily逐字段、40组×8指标、36项补货/P95及报告前五。库存441、欠单549、需求10800、发货10251、及时满足9547、收入28806654分、建议采购总量1924均正确。原始文件比较前后哈希一致。

图表与看板 **139/139通过**：30个日欠单点、3个仓满足率、36个补货量逐值追溯。另在独立浏览器的1400×1000视口检查截图和SVG文字边界，无网络请求、文字均在SVG视口内。这不等于聊天文件预览已经支持HTML渲染；聊天页现有预览仍显示源码。

隔离复现使用审计副本：从不同cwd、新目录（含空格路径）、原ZIP解压后的源目录均成功，三个全流程运行及基线verify均退出0。禁用网络和第三方导入，写入限定在审计目录；这是标准库审计钩子加源码审核，不是OS级安全沙箱。原始ZIP的23个成员（manifest+22个清单文件）和所有重建包的清单/大小/CRC/SHA256均通过；23个非ZIP文件可逐字节复现。ZIP时间元数据导致原始和再生成ZIP的二进制可能不同，按成员字节和清单验收。

验证器自身27/27不是外部验收结论。**43种独立错误仅检出17种、漏检26种**；30种语义错误分别保留旧封包/独立重新封包，另加13种封包/日志错误，共73次验证运行，34检出、39漏检、无超时/异常/守卫阻塞，也没有打印FAIL却退出0。漏检是错误存在时仍输出27/27 PASS。

主要缺口：将履约改为先新后旧，9行FIFO错误仍过；边界只测验证器自己的sim而非真实分析函数；总体库存+1、分仓收入/满足率、补货组重复等未检出；12种SHA/清单/CRC/ZIP缺失等封包变异全漏检；篡改共享需求常量后生成器和验证器同错仍过；HTML注释中的文件名可掩盖实际缺失引用，协议相对srcset也未识别。原交付数据恰好正确，不证明它能可靠验收下一份数据。

这些缺陷属于被测模型生成的交付验证器，不是项目新增Go回归测试失败。评测不人工修复该验证器以制造通过记录。独立审计完成了模型未执行的复现，不回写任务记录或原始交付，不把外部补充验证算作模型自主完成。

引用仍有3项P2：Python三页只返回标题/HTTP状态，模型可见正文计0，未证明“Python至少两页正文”完成；普通表/STRICT的绝对类型结论遗漏INTEGER PRIMARY KEY、ANY、NULL和无损转换等边界；CSV/JSON序列化文档不足以直接支撑跨文件原子性、写者协调和fsync/rename恢复协议。8个比较单元均有链接，但链接存在不等于结论已获得直接正文支持。


## 已复现的剩余问题

1. 通用HTTP与Python网络访问绕过现有research_session的工具计数、证据缓存和定向正文处理。4次http_request得到大量HTML并offload；随后search_evidence为空；Python又访问7个页面，回执仅输出标题和状态。共5次联网工具调用、11次实际HTTP请求，须分别报告这两个口径，不能仅因fetch_url为0而说没联网。Python正文是否支撑每个报告结论仍需独立核查。
2. 摘要后反复回读脚本/目录，虽然原始约束保留，但缺少可靠的阶段推进与独立收尾预算；后半段仍消耗大量上下文。验证/封包的执行证据不能由计划done或模型自述替代。
3. 自动结构检查只验有限文件结构；任意业务正确性仍依赖生成的验证器，必须另用固定oracle及变异测试验证。
4. ec778ed仍遗漏确认门拒绝回执“用户拒绝了该操作,已跳过。”的前端过滤。G使用原有免确认设置未经过该路径；已于评测后在138915c补修三个确认门拒绝回执，并在后端排除shell拒绝/超时/失败回执。36项前端测试与构建、全service竞态回归通过，新后端已重建并健康检查；不将后修版本冒充G版本。


本地证据目录：`.run/long-task-progress/`（修复回归）和 `.run/long-task-inventory-g/`（G运行与独立审计）。
