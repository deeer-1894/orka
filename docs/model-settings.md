# 用户模型配置

登录后点击顶部模型选择器旁的“模型配置”。选择厂商或自定义兼容服务，填写 API Base URL 与 API Key，点击“获取模型列表”，将需要的模型加入列表，也可直接手动填写模型 ID。勾选“使用我的模型配置”并保存；下一次发送任务生效，已运行任务沿用启动时的配置。

当前适配 OpenAI Chat Completions 兼容协议；厂商预设用于填写地址，不代表支持其所有原生协议。模型列表请求为 `<base_url>/models`。不提供此接口、请求失败或没有返回模型时，可以手动填写模型列表。Base URL 应包含服务要求的 API 前缀，例如 `/v1` 或 `/compatible-mode/v1`，不应包含 `/chat/completions`。

每个用户有一份当前使用的配置；关闭“使用我的模型配置”恢复部署默认模型，保留可编辑的个人配置。顶部模型选择器只保留 Auto 和模型名称。Auto 使用列表第一个模型，手动选择固定使用指定模型，不进行主次分级或自动升级。调整列表顺序即可更改 Auto 默认模型。旧配置自动将原默认模型放在列表首位；旧的次模型角色不再生效。

“配置文件 · 导入 / 导出”提供可移植 JSON，例如：

```json
{
  "version": 2,
  "provider": "custom",
  "base_url": "http://localhost:11434/v1",
  "models": ["your-model"],
  "enabled": true
}
```

导出不含 API Key；粘贴配置也不会导入密钥。需要在密码框中单独填写。保存后的密钥只显示“已保存”；同一地址下留空保持现有密钥，改变地址不会复用旧密钥。服务端配置保存在存储根目录旁的 `model-settings` 目录，文件名使用用户标识的哈希，文件权限为 `0600`，不放进工具容器挂载的工作区。

获取模型列表会进行超时和响应大小限制，拒绝重定向，避免将密钥转发到其他地址。测试使用本地兼容服务验证模型发现、保存、模型选择和实际聊天请求；真实厂商连通性需要对应的有效密钥。

同一用户、地址与密钥的请求共享并发限制，跨会话不会重复建立独立限流。运行固定启动时的配置；追问携带原回答的模型与配置版本，配置已改变或旧记录没有版本时跳过，避免将旧内容发送到新服务。
