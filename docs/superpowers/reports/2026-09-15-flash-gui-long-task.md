## 已实现的修复

1. GUI Set-of-Marks 规划器改用异步 SDK 和异步资源关闭，等待供应商响应时可被取消；单次 45 秒，SDK 不隐式重试，避免阻塞 WebSocket 断开检测。
2. 明确每种 GUI 动作需要的字段，特别是 `navigate.url`，降低此前模型只返回动作名导致空 URL 的失败。
3. 仅对明确支持的 `glm-5.3-flash` 设置 `reasoning_effort=low` 与 4096 输出额度；未知模型保留供应商推理默认值。
4. 只解析正常结束的最终输出。截断响应返回错误，隐藏思考内容不会被当作可执行动作。
5. Compose 允许通过环境选择 GUI_PLANNER、VLM_ENABLE、VLM_MODEL 和 MACRO_ENABLE，保留原有默认行为。

能力依据：[Z.ai GLM-5.3-Flash 官方模型卡](https://huggingface.co/zai-org/GLM-5.3-Flash/blob/main/README.md)，包含多模态输入及推理强度说明。GUI 修复范围仅在视觉规划器；没有把这些参数推断应用到未知厂商或其他模型。

验证：4 项新增异步/取消/视觉请求/最终动作回归测试通过；15 项原 UI-TARS 测试在隔离环境中通过；Compose 校验和 `git diff --check` 通过。已构建 `orka-gui:flash-async`，部署到本机 GUI 服务，保留旧容器停止状态用于回退。最终镜像另做真实 GUI 冒烟：9.23 秒内完成导航、点击 Central、从截图读取 Q2 三行及合计，数据与夹具一致。主后端和前端未因这次 GUI 修改重启。

## 仍然存在的问题及后续优先级

### 1. 压缩上下文占位符可能被写入业务文件（高优先级）

事件 8288：模型执行 `file_write`，把 `<persisted-arg>已写入 outputs/observations.md(5455 字符),用 file_read 读取当前内容</persisted-arg>` 当成文件正文，真实覆盖了观察记录。替代文本来源于 `orka_control_layer/service/eino_context.go` 的历史工具参数压缩。模型后来发现并重建了文件，CSV 未受影响，但不能依赖模型自救。

建议将“历史参数已省略”的说明与可执行参数分离，并在写文件边界识别整段压缩占位内容、返回可恢复错误，保留原文件及版本。需要增加“压缩→模型复用→文件写入”集成回归；本轮未实现该修复。

### 2. GUI 动作与最终摘要缺乏一致性验证（高优先级）

GUI 会话 `51081adaf34c218f20421d5b` 在点击 Reset 后页面已恢复 0，随后又输入 15，却声称输入框没有清空。主模型将这个错误归因写进 observations.md 的“页面 UX 行为”。

- [Reset 后真实输入 0 的截图](2026-09-15-flash-gui-evidence/reset-cleared-to-zero.png)
- [代理多执行一次输入后变为 15 的截图](2026-09-15-flash-gui-evidence/agent-typed-again.png)

建议 GUI 任务结束条件与验收证据绑定，区分目标已达成后的多余操作，并让主执行器把动作记录与摘要交叉校验。不能仅凭 `done` 就写入确定性结论。本轮修复动作协议，不等于已解决这种语义误判。

### 3. 主模型单次长生成仍超时（高优先级）

12:17:43 记录 `model call limit: generation deadline exceeded`，任务进入 partial 并展示缺失交付物。累计用量超过旧 800k 上限，未触发新的 2M 总预算上限；此次瓶颈是单次生成而非总预算。

当前主执行器对 Flash 仍使用 180 秒调用限制及默认推理强度，GUI 的低推理设置不会自动影响主模型。应基于实测为 Flash 配置明确能力策略，并把多文件生成拆成小步骤，先写可运行骨架、再逐模块实现与测试；不宜只扩大总预算。本轮未修改主模型策略。

### 4. 模型选择与用量仍有两条配置链路

前端选择的是主模型，GUI 模型由服务端环境独立配置。本轮显式将二者都设为 Flash；不能声称以后前端切换就自动同步 GUI。GUI token 用量也未并入主任务累计预算。后续需要显式的视觉模型能力路由和统一计量，避免用户看见的模型/预算与实际执行不一致。

### 5. GUI 工具稳定性和自报统计

修复后仍有一次 Central/Q3 情景调用在实际执行多步之后超时，重试才完成。模型自己声称的调用次数忽略部分初始失败和额外输入，不能作为正式统计；报告使用事件流重算的结果。动作收据应区分执行前标签、真实输入参数及执行后状态，便于追溯。
