# 运行中追加消息与单按钮输入控件

## 执行语义

`POST /chat/steer` 只接受会话、当前执行 ID、幂等请求 ID、文本和附件。
调用方必须有该会话的编辑权限；服务再校验执行所属用户和会话。
模型、工具范围、审批授权和预算继续使用原任务配置。

每个已准入的执行拥有独立收件箱。HTTP 接收和结束检查使用同一把锁，
避免结束时已确认接收的指令被静默丢弃。追加内容先存入不可变的验收补充记录，
再回显到当前 SSE；传输重试复用请求 ID。模型状态注入通过独立的 Eino middleware 完成。

存在原生检查点时，追加会请求 `CancelAfterToolCalls`：当前工具批次完成后保存原生状态，
完整排空事件迭代器，再在原执行上下文里 Resume。不会取消并重做正在进行的写操作。
在下一次模型调用前注入按顺序收到的人类指令和附件上下文。
如果追加发生在最后一次模型回答期间，则基于最新模型状态继续同一执行，
在处理完新消息前不发出任务完成事件。预算与执行租约不重建。

边界：不抢断正在输出的单次模型调用；主执行委派的子任务也要返回主执行安全边界后
才应用追加要求。停止按钮仍是独立的取消操作。

## 前端

- 空闲：唯一的发送箭头，无输入时禁用。
- 执行中且无文本、无附件：唯一的停止方块。
- 执行中有文本或附件：同一位置切换为发送箭头，调用追加接口。
- 请求失败保留草稿；输入法确认不触发发送。
- 移除“任务结束后另开一轮”的前端队列。
- 会话恢复仅在首次读取完成两份会话列表后执行一次，避免刷新列表时清空新会话。
