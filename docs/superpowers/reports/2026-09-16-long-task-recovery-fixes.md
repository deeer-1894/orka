# 长任务恢复与适度验证修复记录

日期：2026-09-16；分支：`codex/long-task-optimization`。

## 修复

- 未配置输出策略的模型使用供应商默认输出长度，移除默认首轮 4096 / 后续 8192 的强制截断。显式配置仍生效；保留请求超时、用户取消和不完整工具参数隔离。账户、会话、任务累计 token 不设本地额度。
- 恢复失败/中断运行时，接受该会话当前明确选择的工具范围；请求未携带选择时保留历史范围，显式空数组回到自动模式（包括服务已启用的代码执行）。所有者校验与停驻操作确认范围不变。
- 工具检索明确报告未开放的执行能力，不再用无关工具误导代码执行需求。常用 schema 首先可见，其他可用工具按需发现；不会一次发送完整目录的所有 schema。
- 验收区分行数、非空单元格、RFC3339 日期与单个数值。`count` 携带 `column` 现在报明确错误，不能忽略列后假称已验证。保留稳定要求 ID，缺失时明确说明恢复同一 ID，而非误导为缓存问题。
- 重复调用比较规范化参数和结果指纹；提示不再将重复失败说成已经成功。不阻断用户取消，也不新增任务轮次上限。
- 提示词按成果类型明确区分：普通新闻/阅读总结核对来源、日期与事实支持；代码和计算交付才要求真正执行测试。删除强制重复报告渲染、每轮只能做一个动作等要求。
- 指定媒体无法访问时不直接替换其他来源；超时不能推断付费墙或反爬原因。
- 前端旧运行的工具步骤不会因新运行启动而显示“执行中”。删除把普通编号建议列表猜成“执行计划已完成”的旧渲染逻辑，仅结构化计划携带执行状态。
