## 产品代码修复

### HTTP 响应静默截断

真实采集 `gin-gonic/gin/releases?per_page=15` 时，旧实现仅读取 65,536 字节，仍当成功结果返回，导致 JSON 不闭合；读取错误同样被忽略。

将完整响应读取封装为一个有界函数：最多 1 MiB，并多读一个哨兵字节识别超限。完整数据正常返回；超限或读取中断明确失败，建议减小分页，不再提供貌似成功的残缺 JSON。HTTP 4xx/5xx 保留响应正文并标记失败，原有目标地址和重定向检查保留。通过注入 HTTP client 验证真实处理器，不在测试中替换全局状态。

回归覆盖 96 KiB JSON、边界值、读取中断、429 正文及私有地址阻断。工具和执行器测试通过，相关 race 检测通过。部署后在右侧重新获取同一真实响应，完整正文 **68,977 字节**，实际 JSON 解析得到 **15 条记录**。

### HTML 预览来源链接失效

原有 iframe 沙箱使 `target=_blank` 来源链接点击无反应。没有开放 iframe 的弹窗权限，而是提取独立的链接导航模块：只转发真实点击的 HTTP(S) 链接；父页面校验 iframe 来源及本次文档随机标识后，以无 opener/referrer 的新窗口打开。导航引导脚本执行后从文档中删除，随机标识保留在闭包中；加载失败、切换预览时移除对应监听器。

保持 `sandbox="allow-scripts"`，不启用同源和弹窗权限。浏览器回归验证：自动弹窗和程序化点击不能打开窗口，伪造消息无效，预览不能读取主页面登录数据，真实来源点击成功。

前端 75 项单元测试、2 项针对会话文件和导航的浏览器测试通过，生产构建通过。改动按职责分在导航协议、HTML 准备和 React 生命周期中，没有新增产品按钮。

## 长任务产物中发现并纠正的问题

1. 原始页面把 `attention` 数组转成字符串，运行时报 `.map is not a function`，显示“18 条”但表格为空。24 项原有测试未发现。将真实报错插入当前任务后，模型保留 HTML 数组类型、分离 CSV 序列化，并补充回归；修复后独立交互检查通过。
2. 非空非法日期可能进入排序并崩溃。模型修正规范化及测试。
3. 文档的旧测试计数与新日志不同步。收尾核对 README/报告为 28 项，并为保留的 24 项历史日志补充说明，最终重新打包、解压复验。

这些修改位于该会话生成的小项目，不是 Orka 产品源代码。

## 仍需优化

- **工作区文件到浏览器的明确衔接**：当前浏览器与代码执行环境隔离，没有自动打开本会话 HTML 的稳定通道。模型反复猜路径、复制大段页面到脚本，耗时和 token 消耗显著。本轮未把扩大浏览器文件访问权限当作临时修补；后续应实现会话范围的预览入口，并给出明确可用能力与错误。
- **失败后收束与判断依据**：多次同类失败后，模型仍尝试搬运页面，最终需要插入要求收束。后续应依据具体错误和已取得证据减少重复尝试，而不是重新加回任务/token 限额。
- **产物验收的实际覆盖**：文件存在、格式正确、单元测试通过，都不能证明 HTML 能运行。本轮独立浏览器验收确实发现了模型自测遗漏；现有交付检查不能宣称已经验证全部交互。
- **执行说明的精确性**：收尾模型一度误读 README 的模块命令为脚本直跑命令，实际读取后纠正。应减少未经查看当前文件就推测修复原因的行为。
