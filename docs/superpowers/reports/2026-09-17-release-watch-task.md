# 真实长任务：开源依赖版本观察台

请完成一个可实际使用的「开源依赖版本观察台」，供维护 Go + React 项目时查看升级动态。目标项目为 GitHub 上的 cloudwego/eino、chromedp/chromedp、go-chi/chi、gin-gonic/gin、vitejs/vite、facebook/react。

1. 先确认当前日期。从项目官方仓库/官方发布页面收集每个项目最近最多3个正式发布版本（排除预发布、草稿）。记录原始版本号、UTC发布时间、官方发布链接、重要变化摘要、抓取时间和证据文件路径。不能拿抓取时间代替发布时间，不能按版本字符串字典序判断新旧。没有足够可验证版本就保留缺口并解释，不猜测最新版本，不伪造来源。
2. 把实际取得的原始响应或页面证据保存在本会话工作区。用 Python 标准库编写可离线复跑的小项目，分开来源解析、规范化/去重、报告渲染与命令入口；从保存的真实证据构建 releases.json、releases.csv、dashboard.html，不要把手写最终表格冒充可复现解析器。README给出直接可运行的构建和测试命令，不安装额外依赖。
3. dashboard.html 要单文件离线可打开，能按项目筛选、关键字搜索、按发布时间正反排序，显示匹配条数；链接能打开对应官方发布页面。CSV/JSON/HTML来源同一份规范化数据，保留中文、逗号、引号、换行与缺失值，不把未知信息填成0或当前时间。为关键边界写至少12项有意义的测试，并真实执行、保存输出。
4. 写 report.md：概述每个项目的主要升级关注点，区分官方事实、你的判断、未知项；附官方链接与采集覆盖情况，不虚构我们的已安装版本或编造升级收益。尝试实际打开报告页面验证筛选/搜索/排序；若环境限制不能验证交互，要如实列出，不把源码存在当成点击测试通过。
5. 交付 release-watch.zip（包含源码、README、证据、测试、真实日志和报告）以及可直接打开的 dashboard.html、releases.csv、report.md。从最终ZIP新解压后离线运行构建和测试，核对生成记录和报告一致。已有成果不要因重试从头重做，未成功的抓取要保留失败事实并推进可完成部分。

全程自主规划和执行，不需要我选择具体工具，不注册账号，不向外发送消息。完成后用简短中文说明成果、实际验证结果和仍未验证的事项。不要额外扩展成部署或其他项目。
