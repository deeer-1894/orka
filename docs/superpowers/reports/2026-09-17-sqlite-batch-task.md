# 本轮真实长任务

继续增强本会话已经交付的真实 SQLite 备份审计项目。以现有 sqlite-audit-fixed.zip 为基线，在独立的 sqlite-audit-batch/ 目录开发，不改旧 ZIP。不需要重复已有官方资料调研，也不要安装第三方依赖。

1. 修复原报告标题被表名覆盖的问题；中文标题和含HTML特殊字符的表名都必须正确转义。修正文档中“备份开始后的写入一定不包含”的绝对表述，不承诺未实际验证的并发时间点语义。
2. 新增 batch 子命令：接收一个目录，默认只扫描顶层，加 --recursive 扫描子目录；只审计 .db、.sqlite、.sqlite3 文件。不跟随文件/目录符号链接，根目录本身为符号链接要拒绝，不处理 WAL/SHM 伴随文件。复用已有检查模块，不能把单个损坏数据库导致的错误扩散为整个批次丢失；其他数据库继续审计。
3. 生成汇总 JSON 和 CSV，逐项包含相对路径、状态、异常数量、错误摘要，固定按相对路径排序，并给出成功、异常、错误和总数的汇总。空目录也有合法空报告。输出路径不得覆盖任何输入数据库，包括软链接/硬链接别名；JSON/CSV也不能是同一文件。运行前后输入数据库字节必须不变。
4. 退出码规则：全部正常或空目录为0；只有审计异常为1；包含读取/损坏错误或参数错误为2。JSON和CSV须与实际逐库结果一致，UTF-8中文和含逗号/换行的文件名正确处理。代码按发现、审计、汇总、CLI分模块，不堆成一个大函数。
5. 保留并运行原26项测试，新增至少18项有意义的测试，覆盖递归开关、空目录、混合正常与损坏数据库、外键违规、特殊文件名、符号链接目录/文件、输出覆盖保护与真实CLI退出码。仅使用临时测试数据库，不操作任何现有用户数据库。独立验证输入哈希不变，不能把文件哈希与自己比较来凑数。
6. 更新README并逐字运行其中新的示例命令；交付 sqlite-audit-batch.zip（源码、测试、README、研究说明、实际测试日志、示例JSON/CSV）和 validation-batch.md。必须对最终ZIP的新解压副本运行完整测试，并在包外验证记录中写被测ZIP的SHA-256；不要为了把最终哈希写进包里反复重打包。最后提供能点击的下载链接、实际通过/失败数量与未验证项。

请自主完成并在失败后修复，不要只做计划；不为已经有确定结果的步骤重复执行，不编造日志或验收。
