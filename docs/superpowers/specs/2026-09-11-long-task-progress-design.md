# 长任务持续推进与恢复设计

基于F轮失败实测，用户已确认“继续优化跑”。目标是减少纯思考截断及重复工作，让计算后尽早执行验收，并在触限后保留清晰的继续路径。保持当前 codex/long-task-optimization 分支，不改变原始F交付。

选择分层修复：服务层决定模型执行策略和任务状态；llm适配器只负责参数、连续工具调用上下文和完整响应；前端只负责恢复动作及准确的产物归属。相比单纯延长超时，这保留有界成本；相比新增通用业务计算引擎，这避免将库存规则耦合进运行时。

模型返回的reasoning_content在被接受的assistant工具消息中保持至下一请求，摘要仍只保留工作摘要和原始用户要求。截断响应仍完全丢弃、最多一次重试、共180秒，不执行半截工具。已验证当前Ark服务接受DeepSeek V4的reasoning_effort=low并支持工具链回传；对DeepSeek V4明确名称采用low的有界执行策略，其他模型保留原参数默认，不猜测未知模型能力。原有4096首轮/8192后续输出限额不增加。

持久的运行提示在每次压缩后替换更新，要求只推进一个完整小步骤；计算结果先校验守恒、分组、端点和边界，再渲染/报告；尽早形成可执行验证器。提示是行为引导，不等于代码已经实现任意业务的语义验证。现有check_delivery继续承担文件结构检查。

有实际工具进度的call-limit错误落为partial，保留错误详情、累计预算、断点和未完成项。没有实际进度或其他错误不得伪装部分完成；取消仍为取消。聊天页按当前run的真实resumable状态提供断点继续，明确区别重新发送，防重复点击、旧响应与切换会话竞态。

本会话文件优先使用当前消息/计划明确的相对路径及实际存在性；有目录的路径不按basename回退到其他目录；仅思考中的文件名不能证明本轮产生该文件。将纯匹配逻辑独立，覆盖同名旧文件、shell产生但计划声明的文件和未生成文件。

验收：新增行为回归先失败后通过；Go受影响包和竞态、前端逻辑测试与构建通过。重建后端并保留已授权进程配置，浏览器运行同一库存任务G（只换run标识与输出新目录）；记录首工具、reasoning、截断/超时、总耗时、完整交付和独立oracle。即使模型继续失败，也如实保留结果，不以人工修补产物冒充复跑成功。

补充审查约束：传输层缺少终态、损坏帧或响应体提前结束均拒绝，不将半截工具送入执行；完整解析到的用量仍计入预算。自动结构检查仅扫描已声明且改变的小型文件，有文件数/字节/反馈长度上限；未能展示的诊断留待后续批次，最终交付仍重新完整检查。该机制不替代业务断言。
